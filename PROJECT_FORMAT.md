# ELSim project files

The native project extension is `.elsim`. Version 1 is a ZIP archive using ZIP's **stored** (uncompressed) method so it can be generated and opened in browsers without a native helper or third-party ZIP code.

## Layout

```text
manifest.json
project.json
assets/                 # reserved; currently no project assets are supported
```

`manifest.json` follows [`schemas/archive-v1.schema.json`](schemas/archive-v1.schema.json). It identifies the archive version, the `project.json` byte length and CRC-32, and a table of asset paths, byte lengths, media types, CRC-32 values, and optional SHA-256 digests. Version 1 currently requires an empty `assets` array. User-imported model libraries are stored as text in the optional `project.json` `modelAssets` field; they are not repository assets and keep an unknown redistribution status until reviewed by the user.

`project.json` is the versioned document described by [`schemas/project-v7.schema.json`](schemas/project-v7.schema.json). The archive wraps the project without changing its document version. Existing standalone `.elsim.json` files remain readable.

Transient `simulation.initialConditions` accepts either `{ "node": "out", "voltage": "2 V" }` for a labeled node or `{ "element": "L1", "current": "5 mA" }` for an inductor. An inductor condition is valid only when that reference names an inductor in the project; it is emitted as `IC=` on the inductor and automatically enables UIC for transient analysis. A project can store up to eight unique initial conditions. Older node-voltage entries remain valid.

A behavioral source is a two-pin part with `kind: "behavioral"`, `behavioralOutput: "voltage" | "current"`, and an expression in `value`. ELSim accepts numbers, arithmetic and comparison operators, conditionals, `V(node)`/`V(node1,node2)`, `I(component)`, `pi`, `time`, `temper`, `hertz`, and a documented allowlist of mathematical functions. Node references must be labeled and component references must exist. Expressions are limited to 256 characters; directives, comments, quotes, braces, and unknown functions are rejected. For example, `V(vin) > 2.5 ? 5 : 0` creates a threshold-controlled voltage source. Voltage output is measured in volts; current output is measured in amps flowing from pin 1 to pin 2.

Project version 4 added `rootSheetId`, `activeSheetId`, and a bounded `sheets` collection. Each sheet has a stable ID, display name, optional parent ID, scene arrays (parts, wires, junctions, labels), and its own view state. Project version 5 added an ordered `ports` array per sheet and optional `sheetId` on an X subcircuit instance. Project version 6 adds optional named numeric `parameters` on a sheet and `sheetParameters` overrides on its placed X instances. Project version 7 adds per-port `side` (`auto`, `left`, `right`, `top`, `bottom`) and `direction` (`input`, `output`, `inout`) metadata, plus a matching ordered `sheetPortLayout` on placed sheet blocks. Older projects retain automatic alternating pin placement when migrated. A port exposes a same-named labeled node; pin order follows the stored ports order. New blocks place terminals on their configured sides; directions are descriptive electrical-interface metadata and do not alter SPICE pin order. The editor can create nested sheets, switch between them, expose labels as ports, place a child sheet as a reusable block, and persist independent edits and views. The active sheet is the simulation entry circuit. Netlisting emits ngspice `.SUBCKT` definitions and X instances for nested sheet blocks; cyclic block references and stale pin maps are rejected. A component value in a parameterized sheet can use `{PARAM}` and each instance can override the declared numeric default. Generated definitions use ngspice `PARAMS:` syntax; parameterized instance expressions are restricted to one declared identifier, and override/default values are numeric SPICE scalars. The project does not copy generated sheet models into user-imported library assets.


Parts may include a bounded `extensions.ltspice.attributes` map for imported component `SYMATTR` records that ELSim does not interpret. `InstName` and the selected `Value` (or `Value2` when `Value` is absent) map to native instance fields; other attribute names, including `Value2` when `Value` is present, are retained in uppercase with at most 16 records of 512 characters each. This metadata survives `.elsim` round trips, does not affect simulation, and is reported as omitted when generated LTspice export cannot map it.

Project version 2 introduced optional `plotSettings` with selected trace IDs and independent normalized horizontal view ranges for transient, AC, and DC sweep plots. Readers add empty plot settings when opening older projects. Plot preferences do not change the electrical revision timestamp. Simulation samples themselves are not embedded; saved trace IDs are restored when a compatible simulation result is produced again.

Transient `simulation.parameterSweeps` may contain one or two distinct component references, each with `start`, `stop`, and `points` fields. Supported components are resistors, capacitors, inductors, scalar DC voltage sources (`sourceMode: "dc"`), and independent scalar DC current sources. Each axis has 2–10 points and the product is capped at 10 runs. Source values may be signed or zero; passive values must be positive. Voltage pulse/PWL stepping is rejected because ngspice `alter` changes the scalar source level, not waveform tables. The worker creates each run with explicit `alter`, `run`, and `write` commands and returns separate result data. This is ELSim project metadata; it does not serialize ngspice control commands into the project.

Transient measurements accept node-voltage vectors, device-current vectors, and independent current-source vectors such as `i(@I1[current])`. ngspice does not return a scalar `.meas` result for the current-source parameter vector, so ELSim calculates MAX, MIN, AVG, RMS, and DELAY from the same solved raw samples used by the plot. AVG and RMS use trapezoidal time integration; DELAY interpolates threshold-crossing times between adjacent samples. These measurements retain their voltage, ampere, or second units and sweep-case labels.

Parts may optionally store `flipX` (`true` for a horizontal symbol flip). It is presentation state: the electrical pin indexes remain stable, and connected wire endpoints move with their indexed pins. Older version 2 files without this property are interpreted as unflipped.

A voltage source may store `sourceMode: "pulse" | "dc" | "pwl"`, optional pulse timing, or up to 32 `{ "time": "...", "voltage": "..." }` PWL points. An independent current source uses the same modes and pulse timing, with up to 32 `{ "time": "...", "current": "..." }` points in `currentPwl`. Missing pulse fields use defaults of 0 V/A, 0, 1 µs, 1 µs, 50 ms, and 100 ms. `dc` keeps the entered value constant during transient analysis; pulse uses the entered value as its high level; PWL uses strictly increasing, nonnegative time points and does not repeat. If sourceMode is omitted, historical voltage pulse behavior remains and current sources default to scalar DC. DC operating point and DC sweep use the entered value, while AC analysis uses the project-level voltage-source AC magnitude or scalar current-source AC value. LTspice scalar source values import as DC, and standard seven-argument `PULSE(...)` and scalar-pair `PWL(...)` values retain their timing/data points. Parameter stepping accepts only DC source modes.
Current-source components use `kind: "currentSource"`, an `I` reference designator, and an ampere-valued high level such as `1 mA`. Positive current flows from pin 1 to pin 2. Omitted `sourceMode` or `sourceMode: "dc"` means a constant current. `sourceMode: "pulse"` uses the optional shared `pulse` timing fields and the component value as the high current; omitted pulse fields use ELSim defaults. Pulse current stepping is not supported. The current is saved and probed with ngspice's `@i[current]` vector. LTspice PULSE current values import and export; PWL current values remain untranslated and produce an import warning.


An imported subcircuit instance uses `kind: "subcircuit"`, an `X` reference designator, `modelName`, and `modelPins` in declared SPICE order. Pin locations derive from the stored ordered names, and project validation requires an exact match with a subcircuit definition in `modelAssets`. `modelParameters` may hold up to 32 numeric scalar overrides for parameters declared in the subcircuit's `PARAMS:` header; omitted overrides use the library defaults. The netlister emits an `X` instance and its project-owned library text. Removing a library used by instances is blocked in the editor. This does not guarantee every vendor model dialect is supported; ngspice remains the compatibility authority.

Project version 2 may include up to 16 `modelAssets`. Each records the user-selected filename, original UTF-8 text, SHA-256 digest, import time, and `licenseStatus: "unknown"`. A library must contain at least one complete `.SUBCKT` or top-level `.MODEL` card; shared `.PARAM`, `.FUNC`, and `.GLOBAL` records are also retained. External includes and control/end directives are rejected. D, NPN, and PNP `.MODEL` cards can be assigned to matching built-in devices; other card types are retained in the project and netlist but are not yet selectable on schematic devices. Current limit is 4 MiB per library and 10 MiB total. Importing does not grant redistribution rights; imported text stays local to the project archive and is not uploaded by ELSim.

Project version 2 may also include up to 32 user-imported `symbolAssets`, each storing the original UTF-8 `.asy` text, SHA-256 digest, import time, and `licenseStatus: "unknown"`. Current limits are 1 MiB per symbol and 5 MiB total. ELSim reads a bounded subset of LINE, RECTANGLE, CIRCLE, SYMATTR, PIN, and PINATTR records; unknown records are ignored with diagnostics, while malformed or incomplete pins are rejected. A subcircuit instance can reference an imported symbol only when the symbol's `SpiceOrder` and `PinName` values match the `.SUBCKT` pin list exactly. The instance persists pin offsets in SPICE order, which drive wire attachment; the simulator continues to netlist using the model's declared order. Imported symbol artwork is user-provided and is not included in ELSim source distributions by this feature. Import does not grant redistribution rights.

The LTspice import action accepts a parent `.asc` file, optional matching child `.asc` files, and `.asy` sidecars. It maps two-point WIRE records, FLAG labels, supported SYMBOL placements, instance names/values, and `.tran`, `.op`, `.ac`, or `.dc` TEXT directives. `IOPIN` plus a same-coordinate `FLAG` creates ordered sheet-port metadata. A no-Prefix block symbol links to a child `.asc` with the matching basename when its `SpiceOrder` pins match the child's ports; the child becomes a native ELSim sheet block. Repeated instances share that sheet definition, and nested child-of-child sheets are recursively linked with remapped references. Supported imported symbol pins set component terminal coordinates in the ELSim project. Missing sidecars, unknown devices, model references, unmatched hierarchy files, unsupported records, and untranslated directives appear as import diagnostics. The project retains the exact original root `.asc` text under `importedSchematicSource` and child `.asc` sources under `importedChildSchematicSources`; this provenance survives `.elsim` archive save/open. It is not merged into edited schematic data. Unsupported component instances are skipped with diagnostics while parsed wires and flags remain. `.asy` and model files are user-provided; do not redistribute them unless their rights permit it.

## LTspice export

The **Export LTspice** action generates a separate ZIP from the current edited project model. It contains generated `.asc` files, generated component and hierarchical `.asy` files, referenced user model libraries, `elsim-export.json`, and `loss-report.md`. Original imported schematic text and imported symbol artwork are retained as provenance in the `.elsim` project; they are not replayed or copied into LTspice output. Unsupported topology or components block export, and the preview lists known transformations and omissions before download. Model libraries whose redistribution status is unknown are identified by filename and SHA-256, and require a user acknowledgement; that acknowledgement does not grant redistribution rights. Generated paths are sanitized for cross-platform filenames, including Windows device-name restrictions. This is a bounded, stored (uncompressed) ZIP with a separate 100 MiB total / 20 MiB per-entry / 256-entry write limit; the `.elsim` reader limits below still describe only project archives. Generated output has not yet been verified by opening and simulating it in native LTspice, so follow the release verification gate in [LTSPICE_EXPORT.md](LTSPICE_EXPORT.md).

## Reader limits

The browser reader accepts only ZIP stored entries with UTF-8 names, a single disk, no encryption, and no ZIP64. It rejects absolute paths, drive paths, backslashes, `.`/`..` path segments, duplicate names, mismatched local/central headers, overlapping entries, CRC failures, and unknown archive contents. Archives are limited to 50 MiB total, 20 MiB per entry, and 64 entries. These limits apply before project JSON is parsed. The writer uses fixed ZIP timestamps and stable entry ordering for deterministic output.

CRC-32 detects accidental corruption; it is not an authenticity or security signature. Future embedded assets must have recorded provenance and licenses. A user having a model file does not imply permission to redistribute it.

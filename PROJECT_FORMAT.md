# ELSim project files

The native project extension is `.elsim`. The writer emits archive manifest version 2. It stores `manifest.json` and uses ZIP **DEFLATE** (method 8) for `project.json` when compression makes the file smaller; it falls back to stored entries when raw-DEFLATE streaming is unavailable or would not reduce the file. The browser reader remains compatible with version 1 archives, which use stored entries only. Project schemas are independent of archive versions.

## Layout

```text
manifest.json
project.json
assets/                 # reserved; currently no project assets are supported
```

`manifest.json` follows [`schemas/archive-v2.schema.json`](schemas/archive-v2.schema.json) for newly written files. It identifies the archive version, the uncompressed `project.json` byte length and CRC-32, and a table of asset paths, byte lengths, media types, CRC-32 values, and optional SHA-256 digests. Version 2 currently requires an empty `assets` array. The reader also accepts version 1 manifests, validated by [`schemas/archive-v1.schema.json`](schemas/archive-v1.schema.json), and requires all version 1 entries to be stored. User-imported model libraries are stored as text in the optional `project.json` `modelAssets` field; they are not repository assets and keep an unknown redistribution status until reviewed by the user.

`project.json` is the versioned document described by [`schemas/project-v8.schema.json`](schemas/project-v8.schema.json). The archive wraps the project without changing its document version. Existing standalone `.elsim.json` files remain readable.

Transient `simulation.initialConditions` accepts `{ "node": "out", "voltage": "2 V" }` for a labeled node, `{ "element": "L1", "current": "5 mA" }` for an inductor, `{ "element": "C1", "voltage": "2 V" }` for a capacitor, `{ "diode": "D1", "voltage": "0.2 V" }` for a diode/LED/Zener, `{ "transistor": "Q1", "vbe": "0.7 V", "vce": "5 V" }` for an NPN/PNP instance, or `{ "fet": "M1", "vds": "5 V", "vgs": "2 V", "vbs": "0 V" }` for an NMOS/PMOS instance. Three-terminal JFET, MESFET, and VDMOS conditions omit `vbs`. Element and device conditions require a matching placed component reference. Capacitor, diode, and inductor conditions are emitted as `IC=` on that element; BJT values emit as the Q-device `IC=VBE,VCE` pair; FET values emit as the native device `IC=VDS,VGS[,VBS]` fields (the MOSFET bulk voltage is required). Device initial conditions automatically enable UIC for transient analysis. LTspice `.ic V(node+,node-)=value` imports as a capacitor condition when the named pair matches its ordered terminals; a reversed pair reverses the voltage sign. A project can store up to eight unique initial conditions. Older node-voltage entries remain valid.

A resistor may set the optional part-level `acResistance` string (for example, `"2 kΩ"`). It emits ngspice’s `AC=` instance option and affects small-signal AC analysis only; transient and operating-point analyses continue to use the ordinary resistor value. Omission uses the ordinary value in every analysis. Resistors, lamps, and potentiometers also accept optional `noiseEnabled` (boolean); omission keeps ngspice’s default noise behavior, while `false` emits `NOISY=0` on the resistor instance or both potentiometer branches to exclude their thermal and flicker noise in noise analysis.

Resistors, lamps, potentiometers, capacitors, and inductors may specify optional signed numeric `tc1` and `tc2` strings (for example, `"0.01"` and `"-2e-5"`). ELSim emits them as ngspice's native `TC1=` and `TC2=` instance options; each coefficient may use a SPICE engineering suffix. An explicitly entered instance coefficient overrides the selected model's corresponding coefficient. If omitted, ngspice uses the model card's coefficient or its default. TC1 is the first-order and TC2 the second-order temperature dependence. Resistor-based parts may also specify signed numeric `tce`, emitted as `TCE=` for ngspice's exponential resistance-temperature model; ngspice uses the exponential model when TCE is present. These coefficients are separate from `deviceTemperatureDelta` (`DTEMP`).

Controlled voltage and current switches may set a part-level `switchInitialState` to `"on"` or `"off"`; omission preserves the historical `off` default. The setting is passed as ngspice's native SW/CSW instance flag and seeds the schematic's hysteresis animation. It determines the initial state when the control value begins inside the model's hysteresis band; if the transient operating-point solve overrides it, enabling `skipInitialOperatingPoint` (UIC) applies the selected startup state directly.

An inductor may set `mutualCouplings: [{ "partnerId": "...", "coefficient": "0.98" }]` to couple its pin 1 to another inductor pin 1 in the same sheet. Each array entry is one independent pair and emits one native ngspice `K` card, so a coil can take part in several relationships and multi-winding networks can use different coefficients per pair. Coefficients must be numeric and greater than zero through one. The project stores each pair once, on one owner inductor; duplicate reverse entries are invalid. The older single `mutualCoupling` object is upgraded to a one-entry array when a project is opened. Deleting a partner removes only relationships to that coil; copying all coils remaps their pairs, while copying a subset drops external coupling links.

`simulation.temperature` is an optional decimal string in degrees Celsius. Projects that omit it use 27 °C. Non-default values emit a single top-level ngspice `.temp` directive and apply to temperature-sensitive device models across analyses. Accepted range is −273.15 °C through 10000 °C. Supported passive and semiconductor instances may set either `deviceTemperatureDelta` (relative `DTEMP`) or `deviceTemperature` (absolute `TEMP`); the settings are mutually exclusive. The absolute value replaces circuit temperature for that instance, while `DTEMP` adds to it. Both are bounded so the resulting instance temperature stays in range; BSIM MOSFET models remain excluded from these per-instance options. JFET and MESFET parts may also specify a positive dimensionless `fetAreaFactor`, emitted as the positional `AREA` field after the model name; omission preserves ngspice’s default factor of 1. It is separate from the instance multiplier `M`.

`simulation.shuntResistance` is an optional positive SPICE resistance. When set, ELSim emits ngspice's global `.options rshunt=<ohms>` to connect every analog node to ground through that resistance. This can help circuits with floating nodes or nearly singular matrices, but changes the circuit slightly; it is off by default. The browser build includes XSPICE, which ngspice requires for `RSHUNT`.

`simulation.shuntCapacitance` is an optional positive SPICE capacitance. When set, ELSim emits ngspice's global `.options cshunt=<farads>` to connect every analog node to ground through that capacitance. It may help matrix conditioning but changes node capacitance and can affect AC and transient results; it is off by default.

`simulation.integrationMethod` optionally selects the transient solver method: `trap` for trapezoidal or `gear` for Gear integration. Omission keeps ngspice's default trapezoidal method. Gear integration adds numerical damping that can reduce solver ringing in some circuits, but can also hide real fast behavior; compare results with the default before relying on them. The setting is emitted only for transient analyses.

`simulation.integrationMaxOrder` optionally sets Gear's maximum integration order from 2 through 6. It is valid only with `integrationMethod: "gear"`; omission leaves ngspice's Gear order at its default of 2.

`simulation.transientErrorTolerance` is an optional positive finite number emitted as ngspice `.options trtol=...` for transient analysis only. Ngspice's default is 7; changing this solver tolerance can affect runtime and transient samples. Omission preserves the ngspice default.

`simulation.trapezoidalDampingFactor` is an optional numeric value greater than 0 and less than 0.5, emitted as ngspice `.options xmu=...` only for transient analysis using the default or explicit trapezoidal method. Ngspice's default is 0.5. Lower values can reduce trapezoidal ringing but may excessively damp real oscillation; compare against the default before relying on the result. The setting is ignored when Gear integration is selected.

`simulation.transientTotalIterationLimit` optionally sets ngspice's transient-wide `ITL5` iteration limit from 0 through 1,000,000. Ngspice's default is 5000; `0` disables this total-iteration check. The setting is emitted only for transient analysis. It is separate from `transientIterationLimit` (`ITL4`), which limits iterations at each transient timepoint.

`simulation.transientLowerIterationLimit` optionally sets ngspice's transient lower iteration limit (`ITL3`) to a positive integer from 1 through 1,000,000. Ngspice's manual gives a default of 4. It is emitted only for transient analysis; omission preserves the simulator default.

`simulation.dcSourceSteppingSteps` optionally sets ngspice's `SRCSTEPS` (also known as `ITL6`) to an integer from 0 through 1,000,000. A positive value enables source stepping for the DC operating-point solve; `0` disables it. This convergence method ramps independent sources from zero toward their final values and can help some nonlinear circuits, at the cost of extra solve work. The setting is emitted for all analyses because ngspice may perform an operating-point solve before transient, AC, or noise analysis; omission leaves the solver default unchanged.

`simulation.dcGminStepping` optionally selects ngspice's GMIN stepping mode as the string `"0"`, `"1"`, or `"2"`. Mode `0` skips GMIN stepping, mode `1` selects ngspice's standard sequence (the default), and mode `2` selects the original SPICE 3 sequence. It applies when ngspice is solving an operating point, including the preliminary operating point for AC, noise, and transient analyses. Omission preserves ngspice's default behavior.

`simulation.dcSkipInitialNewtonIteration` optionally emits ngspice `.options noopiter` when `true`, telling the solver to skip its first ordinary Newton iteration and proceed directly to GMIN stepping. It is off by default; omission or `false` preserves ngspice behavior.

`simulation.skipAcOperatingPoint` optionally enables ngspice's `NOOPAC` behavior before AC analysis. This can help linear circuits with ideal LC loops that fail during an unnecessary DC operating-point solve. Ngspice still performs an operating-point solve when it detects nonlinear devices. The option is off by default and is emitted only for AC analysis.

`simulation.startSavingTime` is an optional transient time string. It maps to ngspice's `.tran` `tstart` argument: the solver still integrates from time zero, but waveform samples before this time are not retained. The value must be nonnegative and earlier than `stopTime`; omitting it or leaving it blank saves data from time zero.

A behavioral source is a two-pin part with `kind: "behavioral"`, `behavioralOutput: "voltage" | "current"`, and an expression in `value`. Imported LTspice sources also store `behavioralDialect: "ltspice"` so dialect-specific operators are translated without changing native ELSim/ngspice expressions. In that dialect, `^` is Boolean XOR and `**` is exponentiation; sources without the marker retain ngspice `^` exponentiation. ELSim accepts numbers, arithmetic and comparison operators, conditionals, `V(node)`/`V(node1,node2)`, `I(component)`, `pi`, `time`, `temper`, `hertz`, and a documented allowlist of mathematical functions. In native ngspice expressions, `I()` can reference voltage-source branch currents (for example, `I(V1)`); resistor, capacitor, and other device-current vectors are not available through this expression syntax. Circuit checks and netlist generation report these unsupported references before a solver run. A single-node `V(node)` reference must name a net label; the two terminals in `V(node1,node2)` may also refer to connected unlabeled nets, including ground as `0`. Component references must exist. Expressions are limited to 256 characters; directives, comments, quotes, braces, and unknown functions are rejected. For example, `V(vin) > 2.5 ? 5 : 0` creates a threshold-controlled voltage source. Voltage output is measured in volts; current output is measured in amps flowing from pin 1 to pin 2.

Project version 4 added `rootSheetId`, `activeSheetId`, and a bounded `sheets` collection. Each sheet has a stable ID, display name, optional parent ID, scene arrays (parts, wires, junctions, labels), and its own view state. Project version 5 added an ordered `ports` array per sheet and optional `sheetId` on an X subcircuit instance. Project version 6 adds optional named numeric `parameters` on a sheet and `sheetParameters` overrides on its placed X instances. Project version 7 adds per-port `side` (`auto`, `left`, `right`, `top`, `bottom`) and `direction` (`input`, `output`, `inout`) metadata, plus a matching ordered `sheetPortLayout` on placed sheet blocks. Older projects retain automatic alternating pin placement when migrated. A port exposes a same-named labeled node; pin order follows the stored ports order. New blocks place terminals on their configured sides; directions are descriptive electrical-interface metadata and do not alter SPICE pin order. The editor can create nested sheets, switch between them, expose labels as ports, place a child sheet as a reusable block, and persist independent edits and views. The active sheet is the simulation entry circuit. Netlisting emits ngspice `.SUBCKT` definitions and X instances for nested sheet blocks; cyclic block references and stale pin maps are rejected. A component value in a parameterized sheet can use `{PARAM}` and each instance can override the declared numeric default. Generated definitions use ngspice `PARAMS:` syntax; parameterized instance expressions are restricted to one declared identifier, and override/default values are numeric SPICE scalars. The project does not copy generated sheet models into user-imported library assets.


A voltage source may set `pwlRepeat: "forever"` with `sourceMode: "pwl"` and a 2–32 point `pwl` array. The solver emits ngspice `r=0`; LTspice import/export maps the bounded `PWL REPEAT FOREVER (points) ENDREPEAT` form. Alternatively, `pwlRepeatCount` stores the total number of finite cycles (`1`–`31`); the base point table expands to at most 32 points, and its first and last voltage must match to ensure a continuous repeat boundary. The voltage-source inspector edits this count and limits it based on the current table size. The solver expands finite repeats into an ordinary ngspice PWL table, while LTspice export retains `PWL REPEAT FOR N (...) ENDREPEAT`. LTspice voltage/current `PWL FILE=...` sources are imported when their referenced plain-text table is selected with the schematic; the table must have 2–32 nonnegative, strictly increasing time/value pairs and no header. Parsed data is stored as source points with `pwlFileName` retaining the source filename. LTspice export writes the points inline, so the original external file is not required to simulate or reopen the ELSim project. Repeated current-source PWL, nested repeats, finite repeats with discontinuous cycle boundaries or expanded tables above 32 points, and file-backed tables above 32 points are not supported.

Parts may include a bounded `extensions.ltspice.attributes` map for imported component `SYMATTR` records that ELSim does not interpret. `InstName` and the selected `Value` (or `Value2` when `Value` is absent) map to native instance fields; other attribute names, including `Value2` when `Value` is present, are retained in uppercase with at most 16 records of 512 characters each. This metadata survives `.elsim` round trips, does not affect simulation, and is reported as omitted when generated LTspice export cannot map it.

Project version 2 introduced optional `plotSettings` with selected trace IDs and independent normalized horizontal view ranges for transient, AC, noise, and DC sweep plots. Noise analysis settings are stored in `simulation.noiseSweep` with a labeled output node, independent input-source reference, decade/octave/linear scale, point count, and positive start/stop frequencies. Detached waveform-window position and size are also stored here when present. Up to eight additional plot panels may persist a unique ID, bounds, selected trace IDs, trace colors, component-voltage probe definitions, trace-to-schematic references, independent transient/AC/noise/DC horizontal and value ranges, and an optional second measurement-cursor coordinate per analysis. Panels share the active solved sample cursor while their trace lists, presentation, references, ranges, and second measurement cursors remain independent. Readers add empty plot settings when opening older projects. Plot preferences do not change the electrical revision timestamp. Simulation samples themselves are not embedded; saved trace IDs and cursor positions are restored when a compatible simulation result is produced again.

Transient `simulation.parameterSweeps` supports up to three distinct component references, each with `start`, `stop`, and `points` fields; the Cartesian product is capped at 10 runs. Supported targets include R/C/L/lamp values, scalar DC voltage/current sources, PULSE fields (initial/high levels, delay, rise/fall, width, and period), either a shared amplitude scale for PWL points or one indexed voltage/current point (`pwl.point.1` through `pwl.point.32`), and every represented SINE, EXP, SFFM, and AM numeric waveform field. Store a waveform target in `sourceParameter`, such as `sine.phase`, `pulse.rise`, `pwl.point.2`, `exp.riseTau`, `sffm.modulationIndex`, or `am.carrierFrequency`; endpoints accept SPICE engineering suffixes, with units as appropriate. A sweep may instead store `parameter` to change a numeric field on the selected imported device `.MODEL` card. Source amplitudes may be signed or zero; passive values, source frequencies, positive time constants, and pulse period must be positive. The worker uses `alter` for scalar values, `alterparam` plus `reset` for waveform fields, and `altermod` for imported model parameters, then writes separate result data. This is ELSim project metadata; it does not serialize ngspice control commands into the project.

Transient measurements accept node-voltage vectors, device-current vectors, and independent current-source vectors such as `i(@I1[current])`. Scalar measurements may instead use a bounded ngspice expression, for example `abs(V(vin) * I(V1))`, with MAX, MIN, PEAK-TO-PEAK, AVG, RMS, or time INTEG operations. ELSim validates the expression and its node, voltage-source, and parameter references before generating the netlist. ngspice `I()` expression references are limited to voltage-source branch currents. Expression results are unitless because ELSim does not infer physical units from arbitrary expressions. Native ngspice measurement syntax evaluates these expressions; expression-based measurements are not currently exported to LTspice. ngspice does not return a scalar `.meas` result for the current-source parameter vector, so ELSim calculates MAX, MIN, AVG, RMS, and DELAY from the same solved raw samples used by the plot. AVG and RMS use trapezoidal time integration; DELAY interpolates threshold-crossing times between adjacent samples. Vector measurements retain voltage, ampere, coulomb/volt-second, or second units and sweep-case labels.

Parts may optionally store `flipX` (`true` for a horizontal symbol flip). It is presentation state: the electrical pin indexes remain stable, and connected wire endpoints move with their indexed pins. Older version 2 files without this property are interpreted as unflipped.

A voltage source may also store `sourceMode: "trnoise"` with `trnoise` fields `gaussianRms`, `timeStep`, `flickerExponent`, `flickerAmplitude`, `rtsAmplitude`, `rtsCaptureTime`, and `rtsEmissionTime`. Amplitudes use volts, times use seconds, and the flicker exponent is unitless. This maps to ngspice's experimental `TRNOISE(NA NT NALPHA NAMP RTSAM RTSCAPT RTSEMT)` feature; a positive sample interval is required when any noise amplitude is enabled, flicker exponent must be between 0 and 2 when flicker noise is enabled, and RTS capture/emission times must be positive when RTS is enabled. The source's ordinary `value` remains the DC level. Ngspice currently implements transient noise on voltage sources only; current-source `TRNOISE` is unsupported. Any of the seven TRNOISE fields can be stepped in transient analysis, within the existing 2–10 value and ten-total-combination limits, with unit-aware bounds and the same noise constraints checked before simulation.

A voltage or independent current source may store `sourceMode: "pulse" | "dc" | "pwl" | "sine" | "exp" | "sffm" | "am"`. PULSE uses the shared optional timing fields and source `value` as its high level. PWL stores up to 32 strictly time-ordered, nonnegative `{ "time": "...", "voltage": "..." }` points on voltage sources or `{ "time": "...", "current": "..." }` points in `currentPwl` on current sources. SINE fields are offset, amplitude, frequency, delay, damping, and phase; EXP fields are initial/pulsed levels, rise delay/time constant, and fall delay/time constant; SFFM fields are offset, amplitude, carrier frequency, modulation index, and signal frequency. AM stores `offset`, `modulationOffset`, `modulationAmplitude`, `modulationFrequency`, `carrierFrequency`, `delay`, `modulationPhase`, and `carrierPhase` strings in `part.am`; voltage-level fields use volts and current-level fields use amperes, frequencies use hertz, delay uses seconds, and phases use degrees. The transient AM source follows ngspice's `AM(VO VMO VMA FM FC TD PHASEM PHASEC)` form; both frequencies must be positive and delay nonnegative. Source-specific values are strings in volts, amperes, seconds, hertz, or unitless scalars as appropriate. Both source kinds may also store optional scalar `acMagnitude` and numeric-degree `acPhase` strings for AC analysis. Voltage sources without an AC override use the project-level AC magnitude; current sources without one use their scalar value. Missing pulse fields use defaults of 0 V/A, 0, 1 µs, 1 µs, 50 ms, and 100 ms. If `sourceMode` is omitted, historical voltage pulse behavior remains and current sources default to scalar DC. DC operating point and DC sweep use the entered value. LTspice scalar source values import as DC, PULSE timing and finite cycle counts are preserved, PWL point tables are translated, and `Value2 AC magnitude [phase]` maps to per-source AC settings. Parameter stepping supports scalar values, PULSE high levels, a common PWL point-amplitude scale, SINE/EXP/SFFM amplitudes, every represented AM field, and every TRNOISE field on voltage sources. A sweep may instead store `parameter` for a numeric field on the selected imported device `.MODEL` card; that field must exist in a library attached to the project. All stepping is transient-only and limited to ten total combinations.
Current-source components use `kind: "currentSource"`, an `I` reference designator, and an ampere-valued high level such as `1 mA`. Positive current flows from pin 1 to pin 2. Omitted `sourceMode` or `sourceMode: "dc"` means a constant current. `sourceMode: "pulse"` uses the optional shared `pulse` timing fields and the component value as the high current; omitted pulse fields use ELSim defaults. Pulse high-level stepping and PWL point-amplitude scaling are supported for current sources, and SINE/EXP/SFFM/AM field stepping preserves other waveform fields. Ngspice does not currently implement transient `TRNOISE` on current sources. The current is saved and probed with ngspice's `@i[current]` vector. LTspice scalar, PULSE, SINE, EXP, SFFM, inline PWL, repeated PWL, and selected-file PWL current sources import and export. Forever repeats use ngspice's `r=0` extension; finite repeats expand to at most 32 points and require the first and final currents to match.


An imported subcircuit instance uses `kind: "subcircuit"`, an `X` reference designator, `modelName`, and `modelPins` in declared SPICE order. Pin locations derive from the stored ordered names, and project validation requires an exact match with a subcircuit definition in `modelAssets`. `modelParameters` may hold up to 32 numeric scalar overrides for parameters declared in the subcircuit's `PARAMS:` header; omitted overrides use the library defaults. The netlister emits an `X` instance and its project-owned library text. Removing a library used by instances is blocked in the editor. A project-original five-pin teaching op-amp import example is available in [examples/user-opamp](examples/user-opamp/); it is an educational macromodel with documented limits, not a physical-part model. This does not guarantee every vendor model dialect is supported; ngspice remains the compatibility authority.

Project version 2 may include up to 16 `modelAssets`. Each records the user-selected filename, original UTF-8 text, SHA-256 digest, import time, and `licenseStatus: "unknown"`. Optional `selectedSections` stores the chosen names from a sectioned `.LIB` file. A section name is a single ngspice token and may contain punctuation; whitespace, quotes, and control characters are excluded. A leading `;` or `//` is comment syntax, while a leading `$` is accepted as a section token and `$` comments after `.LIB` arguments remain recognized. This selection does not alter the original text or digest. Optional `sourceUrl` (2048 characters), `licenseReference` (128 characters), and `rightsNotes` (1000 characters) are user-entered provenance notes and survive archive round trips. They are not verified by ELSim and never change `licenseStatus`; users must independently confirm redistribution rights. A library must contain at least one complete `.SUBCKT` or top-level `.MODEL` card; shared `.PARAM`, `.FUNC`, and `.GLOBAL` records are also retained. Single or explicitly selected `.LIB` sections are flattened for the solver; schematic references select matching sections automatically, while unreferenced multi-section files prompt the user. External includes and control/end directives are rejected. Imported `D`, `NPN`, `PNP`, `NJF`, `PJF`, `NMOS`, `PMOS`, and `SW` `.MODEL` cards can be assigned to matching diode/LED/Zener, BJT, JFET, MOSFET, and voltage-controlled-switch components. Other model types are retained in the project library and netlist but are not selectable on schematic devices. Current limit is 4 MiB per library and 10 MiB total. Importing does not grant redistribution rights; imported text stays local to the project archive and is not uploaded by ELSim.

Project version 2 may also include up to 32 user-imported `symbolAssets`, each storing original UTF-8 `.asy` or `.elsym` text, its SHA-256 digest, import time, and `licenseStatus: "unknown"`, plus optional user-entered provenance notes. These fields are documentary only and do not verify permission. Current limits are 1 MiB per symbol and 5 MiB total. ELSim reads a bounded subset of LINE, RECTANGLE, CIRCLE, SYMATTR, PIN, and PINATTR records from `.asy`; unknown records are ignored with diagnostics, while malformed or incomplete pins are rejected. Native `.elsym` files use the data-only versioned format in [ELSIM_SYMBOL_FORMAT.md](docs/ELSIM_SYMBOL_FORMAT.md), with bounded vector primitives and ordered pins. A subcircuit instance maps symbol pins to model pins by contiguous `SpiceOrder`; symbol pin names are display labels and may differ from `.SUBCKT` identifiers. The instance persists pin offsets in SPICE order, which drive wire attachment; the simulator continues to netlist using the model's declared order. Imported symbol artwork is user-provided and is not included in ELSim source distributions by this feature. Import does not grant redistribution rights.

The LTspice import action accepts a parent `.asc` file, optional matching child `.asc` files, and `.asy` sidecars. It maps two-point WIRE records, FLAG labels, supported SYMBOL placements, instance names/values, and `.tran`, `.op`, `.ac`, or `.dc` TEXT directives. `IOPIN` plus a same-coordinate `FLAG` creates ordered sheet-port metadata. A no-Prefix block symbol links to a child `.asc` with the matching basename when its `SpiceOrder` pins match the child's ports; the child becomes a native ELSim sheet block. Repeated instances share that sheet definition, and nested child-of-child sheets are recursively linked with remapped references. Supported imported symbol pins set component terminal coordinates in the ELSim project. Missing sidecars, unknown devices, model references, unmatched hierarchy files, unsupported records, and untranslated directives appear as import diagnostics. The project retains the exact original root `.asc` text under `importedSchematicSource` and child `.asc` sources under `importedChildSchematicSources`; this provenance survives `.elsim` archive save/open. Each retained source can also store optional user-entered `sourceUrl` (2048 characters), `licenseReference` (128 characters), and `rightsNotes` (1000 characters). These are unverified notes only: they do not establish a license or change the unknown redistribution-rights status. Original source text is not merged into edited schematic data. Unsupported component instances are skipped with diagnostics while parsed wires and flags remain. `.asy` and model files are user-provided; do not redistribute them unless their rights permit it.

## LTspice export

The **Export LTspice** action generates a separate ZIP from the current edited project model. It contains generated `.asc` files, generated component and hierarchical `.asy` files, referenced user model libraries, `elsim-export.json`, and `loss-report.md`. Original imported schematic text and imported symbol artwork are retained as provenance in the `.elsim` project; they are not replayed or copied into LTspice output. Unsupported topology or components block export, and the preview lists known transformations and omissions before download. Model libraries whose redistribution status is unknown are identified by filename and SHA-256, and require a user acknowledgement; that acknowledgement does not grant redistribution rights. Generated paths are sanitized for cross-platform filenames, including Windows device-name restrictions. This is a bounded, stored (uncompressed) ZIP with a separate 100 MiB total / 20 MiB per-entry / 256-entry write limit; the `.elsim` reader limits below still describe only project archives. Generated output has not yet been verified by opening and simulating it in native LTspice, so follow the release verification gate in [LTSPICE_EXPORT.md](LTSPICE_EXPORT.md).

## Reader limits

The browser reader accepts ZIP stored and raw-DEFLATE entries with UTF-8 names, a single disk, no encryption, and no ZIP64. Version 1 archives must use stored entries; version 2 allows stored or raw-DEFLATE entries. It rejects unsupported flags/methods, absolute paths, drive paths, backslashes, `.`/`..` path segments, duplicate names, mismatched local/central headers, overlapping entries, CRC failures, and unknown archive contents. Archives are limited to 50 MiB compressed and uncompressed total, 49 MiB uncompressed per entry, and 64 entries. Only `manifest.json` and `project.json` are currently accepted. Inflate is streamed and stops as soon as output exceeds the declared size or total/entry limit, then checks the exact size and CRC before parsing project JSON. The project entry may use the larger limit because imported model, symbol, and original schematic text are inline in `project.json`; the total archive limit still applies before project JSON is parsed. The writer uses fixed ZIP timestamps and stable entry ordering. Canonical project JSON is stable across runs; DEFLATE byte-for-byte output is not guaranteed to match across browser implementations.

CRC-32 detects accidental corruption; it is not an authenticity or security signature. Future embedded assets must have recorded provenance and licenses. A user having a model file does not imply permission to redistribute it.

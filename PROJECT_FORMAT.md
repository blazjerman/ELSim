# ELSim project files

The native project extension is `.elsim`. Version 1 is a ZIP archive using ZIP's **stored** (uncompressed) method so it can be generated and opened in browsers without a native helper or third-party ZIP code.

## Layout

```text
manifest.json
project.json
assets/                 # reserved; currently no project assets are supported
```

`manifest.json` follows [`schemas/archive-v1.schema.json`](schemas/archive-v1.schema.json). It identifies the archive version, the `project.json` byte length and CRC-32, and a table of asset paths, byte lengths, media types, CRC-32 values, and optional SHA-256 digests. Version 1 currently requires an empty `assets` array. User-imported model libraries are stored as text in the optional `project.json` `modelAssets` field; they are not repository assets and keep an unknown redistribution status until reviewed by the user.

`project.json` is the versioned document described by [`schemas/project-v7.schema.json`](schemas/project-v7.schema.json). The archive wraps the project without changing its document version. Existing standalone `.elsim.json` files remain readable.

Project version 4 added `rootSheetId`, `activeSheetId`, and a bounded `sheets` collection. Each sheet has a stable ID, display name, optional parent ID, scene arrays (parts, wires, junctions, labels), and its own view state. Project version 5 added an ordered `ports` array per sheet and optional `sheetId` on an X subcircuit instance. Project version 6 adds optional named numeric `parameters` on a sheet and `sheetParameters` overrides on its placed X instances. Project version 7 adds per-port `side` (`auto`, `left`, `right`, `top`, `bottom`) and `direction` (`input`, `output`, `inout`) metadata, plus a matching ordered `sheetPortLayout` on placed sheet blocks. Older projects retain automatic alternating pin placement when migrated. A port exposes a same-named labeled node; pin order follows the stored ports order. New blocks place terminals on their configured sides; directions are descriptive electrical-interface metadata and do not alter SPICE pin order. The editor can create nested sheets, switch between them, expose labels as ports, place a child sheet as a reusable block, and persist independent edits and views. The active sheet is the simulation entry circuit. Netlisting emits ngspice `.SUBCKT` definitions and X instances for nested sheet blocks; cyclic block references and stale pin maps are rejected. A component value in a parameterized sheet can use `{PARAM}` and each instance can override the declared numeric default. Generated definitions use ngspice `PARAMS:` syntax; parameterized instance expressions are restricted to one declared identifier, and override/default values are numeric SPICE scalars. The project does not copy generated sheet models into user-imported library assets.

Project version 2 introduced optional `plotSettings` with selected trace IDs and independent normalized horizontal view ranges for transient, AC, and DC sweep plots. Readers add empty plot settings when opening older projects. Plot preferences do not change the electrical revision timestamp. Simulation samples themselves are not embedded; saved trace IDs are restored when a compatible simulation result is produced again.

Parts may optionally store `flipX` (`true` for a horizontal symbol flip). It is presentation state: the electrical pin indexes remain stable, and connected wire endpoints move with their indexed pins. Older version 2 files without this property are interpreted as unflipped.

An imported subcircuit instance uses `kind: "subcircuit"`, an `X` reference designator, `modelName`, and `modelPins` in declared SPICE order. Pin locations derive from the stored ordered names, and project validation requires an exact match with a subcircuit definition in `modelAssets`. `modelParameters` may hold up to 32 numeric scalar overrides for parameters declared in the subcircuit's `PARAMS:` header; omitted overrides use the library defaults. The netlister emits an `X` instance and its project-owned library text. Removing a library used by instances is blocked in the editor. This does not guarantee every vendor model dialect is supported; ngspice remains the compatibility authority.

Project version 2 may include up to 16 `modelAssets`. Each records the user-selected filename, original UTF-8 text, SHA-256 digest, import time, and `licenseStatus: "unknown"`. A library must contain at least one complete `.SUBCKT` or top-level `.MODEL` card; shared `.PARAM`, `.FUNC`, and `.GLOBAL` records are also retained. External includes and control/end directives are rejected. D, NPN, and PNP `.MODEL` cards can be assigned to matching built-in devices; other card types are retained in the project and netlist but are not yet selectable on schematic devices. Current limit is 4 MiB per library and 10 MiB total. Importing does not grant redistribution rights; imported text stays local to the project archive and is not uploaded by ELSim.

Project version 2 may also include up to 32 user-imported `symbolAssets`, each storing the original UTF-8 `.asy` text, SHA-256 digest, import time, and `licenseStatus: "unknown"`. Current limits are 1 MiB per symbol and 5 MiB total. ELSim reads a bounded subset of LINE, RECTANGLE, CIRCLE, SYMATTR, PIN, and PINATTR records; unknown records are ignored with diagnostics, while malformed or incomplete pins are rejected. A subcircuit instance can reference an imported symbol only when the symbol's `SpiceOrder` and `PinName` values match the `.SUBCKT` pin list exactly. The instance persists pin offsets in SPICE order, which drive wire attachment; the simulator continues to netlist using the model's declared order. Imported symbol artwork is user-provided and is not included in ELSim source distributions by this feature. Import does not grant redistribution rights.

The LTspice import action accepts one `.asc` file together with its `.asy` sidecar files. It maps two-point WIRE records, FLAG labels, supported SYMBOL placements, instance names/values, and `.tran`, `.op`, `.ac`, or `.dc` TEXT directives. Supported imported symbol pins set component terminal coordinates in the ELSim project. Missing sidecars, unknown devices, model references, unsupported records, and untranslated directives appear in the project inspector as import diagnostics. The importer does not yet preserve unrecognized `.asc` lines, resolve hierarchy, load model files by path, or round-trip back to LTspice; unsupported component instances are skipped with diagnostics while parsed wires and flags remain. `.asy` files are user-provided; do not redistribute them unless their rights permit it.

## Reader limits

The browser reader accepts only ZIP stored entries with UTF-8 names, a single disk, no encryption, and no ZIP64. It rejects absolute paths, drive paths, backslashes, `.`/`..` path segments, duplicate names, mismatched local/central headers, overlapping entries, CRC failures, and unknown archive contents. Archives are limited to 50 MiB total, 20 MiB per entry, and 64 entries. These limits apply before project JSON is parsed. The writer uses fixed ZIP timestamps and stable entry ordering for deterministic output.

CRC-32 detects accidental corruption; it is not an authenticity or security signature. Future embedded assets must have recorded provenance and licenses. A user having a model file does not imply permission to redistribute it.

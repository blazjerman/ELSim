# ELSim project files

The native project extension is `.elsim`. Version 1 is a ZIP archive using ZIP's **stored** (uncompressed) method so it can be generated and opened in browsers without a native helper or third-party ZIP code.

## Layout

```text
manifest.json
project.json
assets/                 # reserved; currently no project assets are supported
```

`manifest.json` follows [`schemas/archive-v1.schema.json`](schemas/archive-v1.schema.json). It identifies the archive version, the `project.json` byte length and CRC-32, and a table of asset paths, byte lengths, media types, CRC-32 values, and optional SHA-256 digests. Version 1 currently requires an empty `assets` array. User-imported model libraries are stored as text in the optional `project.json` `modelAssets` field; they are not repository assets and keep an unknown redistribution status until reviewed by the user.

`project.json` is the versioned document described by [`schemas/project-v8.schema.json`](schemas/project-v8.schema.json). The archive wraps the project without changing its document version. Existing standalone `.elsim.json` files remain readable.

Transient `simulation.initialConditions` accepts `{ "node": "out", "voltage": "2 V" }` for a labeled node, `{ "element": "L1", "current": "5 mA" }` for an inductor, or `{ "element": "C1", "voltage": "2 V" }` for a capacitor. Element conditions require a matching inductor or capacitor reference; they are emitted as `IC=` on that element and automatically enable UIC for transient analysis. LTspice `.ic V(node+,node-)=value` imports as a capacitor condition when the named pair matches its ordered terminals; a reversed pair reverses the voltage sign. A project can store up to eight unique initial conditions. Older node-voltage entries remain valid.

`simulation.temperature` is an optional decimal string in degrees Celsius. Projects that omit it use 27 °C. Non-default values emit a single top-level ngspice `.temp` directive and apply to temperature-sensitive device models across analyses. Accepted range is −273.15 °C through 10000 °C.

A behavioral source is a two-pin part with `kind: "behavioral"`, `behavioralOutput: "voltage" | "current"`, and an expression in `value`. Imported LTspice sources also store `behavioralDialect: "ltspice"` so dialect-specific operators are translated without changing native ELSim/ngspice expressions. In that dialect, `^` is Boolean XOR and `**` is exponentiation; sources without the marker retain ngspice `^` exponentiation. ELSim accepts numbers, arithmetic and comparison operators, conditionals, `V(node)`/`V(node1,node2)`, `I(component)`, `pi`, `time`, `temper`, `hertz`, and a documented allowlist of mathematical functions. A single-node `V(node)` reference must name a net label; the two terminals in `V(node1,node2)` may also refer to connected unlabeled nets, including ground as `0`. Component references must exist. Expressions are limited to 256 characters; directives, comments, quotes, braces, and unknown functions are rejected. For example, `V(vin) > 2.5 ? 5 : 0` creates a threshold-controlled voltage source. Voltage output is measured in volts; current output is measured in amps flowing from pin 1 to pin 2.

Project version 4 added `rootSheetId`, `activeSheetId`, and a bounded `sheets` collection. Each sheet has a stable ID, display name, optional parent ID, scene arrays (parts, wires, junctions, labels), and its own view state. Project version 5 added an ordered `ports` array per sheet and optional `sheetId` on an X subcircuit instance. Project version 6 adds optional named numeric `parameters` on a sheet and `sheetParameters` overrides on its placed X instances. Project version 7 adds per-port `side` (`auto`, `left`, `right`, `top`, `bottom`) and `direction` (`input`, `output`, `inout`) metadata, plus a matching ordered `sheetPortLayout` on placed sheet blocks. Older projects retain automatic alternating pin placement when migrated. A port exposes a same-named labeled node; pin order follows the stored ports order. New blocks place terminals on their configured sides; directions are descriptive electrical-interface metadata and do not alter SPICE pin order. The editor can create nested sheets, switch between them, expose labels as ports, place a child sheet as a reusable block, and persist independent edits and views. The active sheet is the simulation entry circuit. Netlisting emits ngspice `.SUBCKT` definitions and X instances for nested sheet blocks; cyclic block references and stale pin maps are rejected. A component value in a parameterized sheet can use `{PARAM}` and each instance can override the declared numeric default. Generated definitions use ngspice `PARAMS:` syntax; parameterized instance expressions are restricted to one declared identifier, and override/default values are numeric SPICE scalars. The project does not copy generated sheet models into user-imported library assets.


A voltage source may set `pwlRepeat: "forever"` with `sourceMode: "pwl"` and a 2–32 point `pwl` array. The solver emits ngspice `r=0`; LTspice import/export maps the bounded `PWL REPEAT FOREVER (points) ENDREPEAT` form. Alternatively, `pwlRepeatCount` stores the total number of finite cycles (`1`–`31`); the base point table expands to at most 32 points, and its first and last voltage must match to ensure a continuous repeat boundary. The voltage-source inspector edits this count and limits it based on the current table size. The solver expands finite repeats into an ordinary ngspice PWL table, while LTspice export retains `PWL REPEAT FOR N (...) ENDREPEAT`. LTspice voltage/current `PWL FILE=...` sources are imported when their referenced plain-text table is selected with the schematic; the table must have 2–32 nonnegative, strictly increasing time/value pairs and no header. Parsed data is stored as source points with `pwlFileName` retaining the source filename. LTspice export writes the points inline, so the original external file is not required to simulate or reopen the ELSim project. Repeated current-source PWL, nested repeats, finite repeats with discontinuous cycle boundaries or expanded tables above 32 points, and file-backed tables above 32 points are not supported.

Parts may include a bounded `extensions.ltspice.attributes` map for imported component `SYMATTR` records that ELSim does not interpret. `InstName` and the selected `Value` (or `Value2` when `Value` is absent) map to native instance fields; other attribute names, including `Value2` when `Value` is present, are retained in uppercase with at most 16 records of 512 characters each. This metadata survives `.elsim` round trips, does not affect simulation, and is reported as omitted when generated LTspice export cannot map it.

Project version 2 introduced optional `plotSettings` with selected trace IDs and independent normalized horizontal view ranges for transient, AC, and DC sweep plots. Detached waveform-window position and size are also stored here when present. Up to eight additional plot panels may persist a unique ID, bounds, selected trace IDs, and independent transient/AC/DC horizontal ranges; panels share the active solved sample cursor. Readers add empty plot settings when opening older projects. Plot preferences do not change the electrical revision timestamp. Simulation samples themselves are not embedded; saved trace IDs are restored when a compatible simulation result is produced again.

Transient `simulation.parameterSweeps` supports up to three distinct component references, each with `start`, `stop`, and `points` fields; the Cartesian product is capped at 10 runs. Supported targets include R/C/L/lamp values, scalar DC voltage/current sources, PULSE fields (initial/high levels, delay, rise/fall, width, and period), either a shared amplitude scale for PWL points or one indexed voltage/current point (`pwl.point.1` through `pwl.point.32`), and every represented SINE, EXP, and SFFM numeric waveform field. Store a waveform target in `sourceParameter`, such as `sine.phase`, `pulse.rise`, `pwl.point.2`, `exp.riseTau`, or `sffm.modulationIndex`; endpoints accept SPICE engineering suffixes, with units as appropriate. A sweep may instead store `parameter` to change a numeric field on the selected imported device `.MODEL` card. Source amplitudes may be signed or zero; passive values, source frequencies, positive time constants, and pulse period must be positive. The worker uses `alter` for scalar values, `alterparam` plus `reset` for waveform fields, and `altermod` for imported model parameters, then writes separate result data. This is ELSim project metadata; it does not serialize ngspice control commands into the project.

Transient measurements accept node-voltage vectors, device-current vectors, and independent current-source vectors such as `i(@I1[current])`. ngspice does not return a scalar `.meas` result for the current-source parameter vector, so ELSim calculates MAX, MIN, AVG, RMS, and DELAY from the same solved raw samples used by the plot. AVG and RMS use trapezoidal time integration; DELAY interpolates threshold-crossing times between adjacent samples. These measurements retain their voltage, ampere, or second units and sweep-case labels.

Parts may optionally store `flipX` (`true` for a horizontal symbol flip). It is presentation state: the electrical pin indexes remain stable, and connected wire endpoints move with their indexed pins. Older version 2 files without this property are interpreted as unflipped.

A voltage or independent current source may store `sourceMode: "pulse" | "dc" | "pwl" | "sine" | "exp" | "sffm"`. PULSE uses the shared optional timing fields and source `value` as its high level. PWL stores up to 32 strictly time-ordered, nonnegative `{ "time": "...", "voltage": "..." }` points on voltage sources or `{ "time": "...", "current": "..." }` points in `currentPwl` on current sources. SINE fields are offset, amplitude, frequency, delay, damping, and phase; EXP fields are initial/pulsed levels, rise delay/time constant, and fall delay/time constant; SFFM fields are offset, amplitude, carrier frequency, modulation index, and signal frequency. Source-specific values are strings in volts, amperes, seconds, hertz, or unitless scalars as appropriate. Both source kinds may also store optional scalar `acMagnitude` and numeric-degree `acPhase` strings for AC analysis. Voltage sources without an AC override use the project-level AC magnitude; current sources without one use their scalar value. Missing pulse fields use defaults of 0 V/A, 0, 1 µs, 1 µs, 50 ms, and 100 ms. If `sourceMode` is omitted, historical voltage pulse behavior remains and current sources default to scalar DC. DC operating point and DC sweep use the entered value. LTspice scalar source values import as DC, PULSE timing and finite cycle counts are preserved, PWL point tables are translated, and `Value2 AC magnitude [phase]` maps to per-source AC settings. Parameter stepping supports scalar values, PULSE high levels, a common PWL point-amplitude scale, SINE/EXP/SFFM amplitudes, and the SINE/SFFM frequency targets listed above. A sweep may instead store `parameter` for a numeric field on the selected imported device `.MODEL` card; that field must exist in a library attached to the project. All stepping is transient-only and limited to ten total combinations.
Current-source components use `kind: "currentSource"`, an `I` reference designator, and an ampere-valued high level such as `1 mA`. Positive current flows from pin 1 to pin 2. Omitted `sourceMode` or `sourceMode: "dc"` means a constant current. `sourceMode: "pulse"` uses the optional shared `pulse` timing fields and the component value as the high current; omitted pulse fields use ELSim defaults. Pulse high-level stepping and PWL point-amplitude scaling are supported for current sources, and SINE/EXP/SFFM amplitude stepping preserves their other waveform fields. The current is saved and probed with ngspice's `@i[current]` vector. LTspice scalar, PULSE, SINE, EXP, SFFM, inline PWL, repeated PWL, and selected-file PWL current sources import and export. Forever repeats use ngspice's `r=0` extension; finite repeats expand to at most 32 points and require the first and final currents to match.


An imported subcircuit instance uses `kind: "subcircuit"`, an `X` reference designator, `modelName`, and `modelPins` in declared SPICE order. Pin locations derive from the stored ordered names, and project validation requires an exact match with a subcircuit definition in `modelAssets`. `modelParameters` may hold up to 32 numeric scalar overrides for parameters declared in the subcircuit's `PARAMS:` header; omitted overrides use the library defaults. The netlister emits an `X` instance and its project-owned library text. Removing a library used by instances is blocked in the editor. A project-original five-pin teaching op-amp import example is available in [examples/user-opamp](examples/user-opamp/); it is an educational macromodel with documented limits, not a physical-part model. This does not guarantee every vendor model dialect is supported; ngspice remains the compatibility authority.

Project version 2 may include up to 16 `modelAssets`. Each records the user-selected filename, original UTF-8 text, SHA-256 digest, import time, and `licenseStatus: "unknown"`. Optional `selectedSections` stores the chosen names from a sectioned `.LIB` file; it does not alter the original text or digest. Optional `sourceUrl` (2048 characters), `licenseReference` (128 characters), and `rightsNotes` (1000 characters) are user-entered provenance notes and survive archive round trips. They are not verified by ELSim and never change `licenseStatus`; users must independently confirm redistribution rights. A library must contain at least one complete `.SUBCKT` or top-level `.MODEL` card; shared `.PARAM`, `.FUNC`, and `.GLOBAL` records are also retained. Single or explicitly selected `.LIB` sections are flattened for the solver; schematic references select matching sections automatically, while unreferenced multi-section files prompt the user. External includes and control/end directives are rejected. D, NPN, and PNP `.MODEL` cards can be assigned to matching built-in devices; other card types are retained in the project and netlist but are not yet selectable on schematic devices. Current limit is 4 MiB per library and 10 MiB total. Importing does not grant redistribution rights; imported text stays local to the project archive and is not uploaded by ELSim.

Project version 2 may also include up to 32 user-imported `symbolAssets`, each storing the original UTF-8 `.asy` text, SHA-256 digest, import time, and `licenseStatus: "unknown"`, plus the same optional user-entered provenance notes. These fields are documentary only and do not verify permission. Current limits are 1 MiB per symbol and 5 MiB total. ELSim reads a bounded subset of LINE, RECTANGLE, CIRCLE, SYMATTR, PIN, and PINATTR records; unknown records are ignored with diagnostics, while malformed or incomplete pins are rejected. A subcircuit instance can reference an imported symbol only when the symbol's `SpiceOrder` and `PinName` values match the `.SUBCKT` pin list exactly. The instance persists pin offsets in SPICE order, which drive wire attachment; the simulator continues to netlist using the model's declared order. Imported symbol artwork is user-provided and is not included in ELSim source distributions by this feature. Import does not grant redistribution rights.

The LTspice import action accepts a parent `.asc` file, optional matching child `.asc` files, and `.asy` sidecars. It maps two-point WIRE records, FLAG labels, supported SYMBOL placements, instance names/values, and `.tran`, `.op`, `.ac`, or `.dc` TEXT directives. `IOPIN` plus a same-coordinate `FLAG` creates ordered sheet-port metadata. A no-Prefix block symbol links to a child `.asc` with the matching basename when its `SpiceOrder` pins match the child's ports; the child becomes a native ELSim sheet block. Repeated instances share that sheet definition, and nested child-of-child sheets are recursively linked with remapped references. Supported imported symbol pins set component terminal coordinates in the ELSim project. Missing sidecars, unknown devices, model references, unmatched hierarchy files, unsupported records, and untranslated directives appear as import diagnostics. The project retains the exact original root `.asc` text under `importedSchematicSource` and child `.asc` sources under `importedChildSchematicSources`; this provenance survives `.elsim` archive save/open. Each retained source can also store optional user-entered `sourceUrl` (2048 characters), `licenseReference` (128 characters), and `rightsNotes` (1000 characters). These are unverified notes only: they do not establish a license or change the unknown redistribution-rights status. Original source text is not merged into edited schematic data. Unsupported component instances are skipped with diagnostics while parsed wires and flags remain. `.asy` and model files are user-provided; do not redistribute them unless their rights permit it.

## LTspice export

The **Export LTspice** action generates a separate ZIP from the current edited project model. It contains generated `.asc` files, generated component and hierarchical `.asy` files, referenced user model libraries, `elsim-export.json`, and `loss-report.md`. Original imported schematic text and imported symbol artwork are retained as provenance in the `.elsim` project; they are not replayed or copied into LTspice output. Unsupported topology or components block export, and the preview lists known transformations and omissions before download. Model libraries whose redistribution status is unknown are identified by filename and SHA-256, and require a user acknowledgement; that acknowledgement does not grant redistribution rights. Generated paths are sanitized for cross-platform filenames, including Windows device-name restrictions. This is a bounded, stored (uncompressed) ZIP with a separate 100 MiB total / 20 MiB per-entry / 256-entry write limit; the `.elsim` reader limits below still describe only project archives. Generated output has not yet been verified by opening and simulating it in native LTspice, so follow the release verification gate in [LTSPICE_EXPORT.md](LTSPICE_EXPORT.md).

## Reader limits

The browser reader accepts only ZIP stored entries with UTF-8 names, a single disk, no encryption, and no ZIP64. It rejects absolute paths, drive paths, backslashes, `.`/`..` path segments, duplicate names, mismatched local/central headers, overlapping entries, CRC failures, and unknown archive contents. Archives are limited to 50 MiB total, 49 MiB per entry, and 64 entries. The project entry may use the larger limit because v1 stores imported model, symbol, and original schematic text inside `project.json`; the total archive limit still applies before project JSON is parsed. The writer uses fixed ZIP timestamps and stable entry ordering for deterministic output.

CRC-32 detects accidental corruption; it is not an authenticity or security signature. Future embedded assets must have recorded provenance and licenses. A user having a model file does not imply permission to redistribute it.

# LTspice compatibility matrix

This matrix describes the importer as implemented today. “Supported” means ELSim maps the record into its own project model; it does not promise byte-for-byte round trips or full behavioral equivalence with LTspice. Fixtures are hand-written in the repository and contain no vendor artwork or models.

For an imported `.step param`, a generated parameter used exactly once as a PWL point value maps to that source's indexed point sweep. LTspice `PWL VALUE_SCALE_FACTOR={NAME}` maps back to ELSim's shared PWL value-scale sweep when `NAME` has a numeric `.param` default. PWL point times remain literal; parameterized timing points and parameters shared by multiple circuit fields remain global sweeps. The scale syntax follows the [LTspice independent voltage source reference](https://ltspicehelpmanual.azurewebsites.net/IVoltageSource.htm) and its matching current-source form.

Model-library preflight recognizes LTspice `.MODEL child AKO:base NMOS` inheritance and dimension-selected MOSFET bins such as `.MODEL N1.1 NMOS ... LMIN=... LMAX=... WMIN=... WMAX=...`. Both constructs are preserved on import and reported with their source lines. The pinned browser ngspice runtime rejects the tested AKO card and does not select a suffixed bin from an instance's unsuffixed base model name; ELSim does not expand inheritance or choose bins. Use only model replacements or explicit bin selections verified against their author's intent and ngspice behavior. Hand-written unit tests cover source preservation and diagnostics. LTspice syntax reference: [MOSFET models and bins](https://ltspicehelpmanual.azurewebsites.net/mmosfet.htm).

## Model dialect checks

The compatibility assistant currently detects selected LTspice constructs rather than claiming full dialect validation. Tested diagnostics include encrypted model files, `uplim`/`dnlim` handling through ngspice `lta` (including SPICE `+` continuation lines), raw-library `limit()` clamp semantics (the pinned WASM build returns 0 V for `limit(4,0,3)` instead of 3 V, including in `lta` mode; native schematic B sources translate to `min(max(x,low),high)` for ordered bounds), unavailable `VSWITCH`, unverified XSPICE `A` devices, B-source `R=`/`P=`, behavioral Laplace options, raw imported-library `table()`, `if()`, and `u()` zero-boundary behavior, plus `limit()`, `mod()`, and inverse-trig aliases (native schematic B sources translate the documented subset, including `buf()`, `inv()`, `u()` (strict zero boundary), `limit()`, `mod()`, `atan2()`, `cbrt()`, and `hypot()`), and `idt()` expressions, and unsupported timestep/Laplace tuning options. B-source checks warn for functions that the pinned WASM engine rejects or handles with incompatible signatures in raw imported model-library text: `absdelay`, `atan2`, `buf`, `cbrt`, `delay`, `flat`, one-argument `gauss`, `hypot`, `int`, `inv`, `mc`, `mod`, `noise`, `pwrs`, `rand`, `random`, `round`, `select`, `smallsig`, `square`, `white`, and `xor`. The pinned WASM regression confirms `flat`, one-argument `gauss`, `mc`, and `select` fail in the browser engine. Unit fixtures check source-line diagnostics, and Chromium verifies that an imported library displays the filename, line, and suggested action; `npm run test:wasm` checks numeric B-source results for Boolean thresholds, `atan2()` quadrants/axes, positive/negative `cbrt()` values, `hypot(3,4)`, the differing `u(0)` boundary values, and positive/negative remainder arithmetic. Imported raw model-library `u()` calls receive a source-line warning because their text is not rewritten. Raw model-library content is not rewritten. They also flag `^` because LTspice defines it as boolean XOR in B-source expressions while this ngspice build evaluates it as exponentiation; the numeric fixture verifies `V(IN)^2` and `pow(V(IN),2)` both produce 9 V at `V(IN)=3`. Use explicit `pow(a,b)` when exponentiation is intended. These differences are based on the [LTspice B-source reference](https://ltspicehelpmanual.azurewebsites.net/barbitrarybehavioralvoltageorcur.htm), the [ngspice manual](https://ngspice.sourceforge.io/docs/ngspice-manual.pdf), and tests of the pinned WASM engine. The raw-library diagnostic suggests `min(max(x,low),high)` for ordered clamp bounds; ELSim preserves imported model source and does not rewrite it. The pinned WASM engine numerically verifies ngspice B-source `min()`, `max()`, and `uramp()` on an input-driven operating-point fixture; this records engine behavior, not full LTspice semantic equivalence. The worker enables `lta` mode when an `uplim`/`dnlim` function appears anywhere in a logical deck record; imported model text is preserved unchanged. XSPICE is enabled in the build, but external `.cm` modules are not packaged or validated, so the new diagnostic is intentionally a warning rather than a claim that every A-device fails.

## Provenance and licensing

The importer does not include LTspice binaries, vendor models, or vendor symbol artwork in ELSim source distributions. User-selected `.asc`, `.asy`, and model files remain project-local source material with unknown redistribution status. Importing a file does not grant rights to redistribute it. See [PROJECT_FORMAT.md](PROJECT_FORMAT.md) for project storage and export warnings.
